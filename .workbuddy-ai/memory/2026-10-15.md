## 多设备同步新增 WebDAV 后端

在既有 `SyncAdapter` 适配器体系（PostgreSQL / MySQL / D1）之外新增 **WebDAV** 同步目标。

设计要点（重要，后续维护请遵循）：

- WebDAV 是文件型存储，无法照搬 SQL 的行级 seq 语义，因此采用**单文档模型**：
  整个同步状态存于 `<prefix>sync.json`（`schemaVersion` / `vault` / `counter` / `items` / `devices` / `rev`），
  每个条目的 payload 以 base64 内联，写入是原子的单次 PUT。
- 并发控制用 **ETag 条件写**：`If-Match` 更新、`If-None-Match: *` 创建；412 → 重读重试
  （`CAS_RETRIES=30`，随机退避 40ms）。服务器不返回强 ETag 时退化为**写入后校验 `rev` 随机版本号**。
- `head()` = `counter`（只在该条目 hlc 更大时才自增 seq，保证 seq 唯一且随提交递增）。
- 无实时推送：`realtime:false`，`defaultPollSec:60`，`defaultReconcileMin:30`。

新增/改动文件：

- `src/main/sync/adapters/webdav-client.ts`（新增）：fetch + Basic 认证 + ETag CAS + 错误码映射 + 凭据脱敏。

- 渲染层：`model.ts`（`WebdavForm` / `buildConfig` / `validateForm` / `describeTarget` / `DB_KINDS`）、
  `ConnectionForm.tsx`（`WebdavConnectionForm` + `WebdavHelp`）、`DbLogo.tsx`（自绘中性云图标，非品牌 logo）、
  `SyncWizard.tsx`（第 4 个卡片，网格改 `@xl:grid-cols-2 @3xl:grid-cols-4`）、`SyncDashboard.tsx`、`SyncIntro.tsx`。

## 修复 `npm run dev` 报 "Error: Electron uninstall"

现象：`electron-vite dev` 在 `starting electron app` 之前抛出 `Error: Electron uninstall`
（来自 electron-vite 的 `getElectronPath()`）。

根因：`node_modules/electron/` 下缺少 `path.txt` 与 `dist/`，即 Electron 二进制**下载了但没解压**
（`~/Library/Caches/electron/7ed81…/electron-v44.7.2-darwin-arm64.zip` 存在，130MB）。
`npm rebuild electron` 不会重新触发该包的 postinstall，需直接执行 `node node_modules/electron/install.js`
（该脚本幂等，已安装则直接 exit 0）。

加固：`scripts/postinstall.cjs` 增加 `ensureElectronBinary()` —— 若 `path.txt` 指向的可执行文件不存在，
自动调用 electron 的 install.js（尊重 `ELECTRON_SKIP_BINARY_DOWNLOAD`，失败时提示设置 `ELECTRON_MIRROR`）。
已验证「正常静默 no-op / 删除 path.txt 后能自动补装」两条路径。

注意：工具沙箱里存在 `ELECTRON_RUN_AS_NODE=1`（会让 Electron 以纯 Node 启动），但**不在用户 shell 配置中**，
仅沙箱注入；沙箱内还会出现 `sandbox initialization failed: Operation not permitted`（Chromium 沙箱/GPU 被限制），
用户本机不受影响。

## 修复 macOS Command+Q 退出报错（主进程未捕获异常）

现象：打包版（`release/0.1.1/mac/SSH Tool.app`）按 Cmd+Q 弹出
`TypeError: Cannot read properties of null (reading 'db') at createWindow`。

根因：macOS 在退出过程中仍会派发 `activate` 事件。时序为
`before-quit`（quitting=true）→ `will-quit`（preventDefault，异步 `ctx.shutdown()`，完成后 `ctx = null` 再 `app.quit()`），
而 `activate` 处理器 `if (BrowserWindow.getAllWindows().length === 0) createWindow()` 会在 `ctx` 已置空时
调用 `createWindow()`，其中 `const c = ctx!` 的非空断言被击穿 → `c.db` 崩溃。

修复（`src/main/index.ts`）：

- `shuttingDown` 提升为模块级变量（原先声明在 `will-quit` 前）。
- `createWindow()` 改为 `const c = ctx; if (!c) return`，去掉非空断言。
- `activate` 处理器加守卫：`if (quitting || shuttingDown) return`（保留「关窗后点 Dock 图标重新开窗」的正常行为）。
- 同类加固：`startAutoLock()` 的 30s 定时器 / `lock-screen` / `suspend` / `resume` 回调都加 `shuttingDown` 守卫，
  避免 shutdown 期间访问已 `db.close()` 的上下文。

## 修复 macOS Command+Q「没有完全退出」（进程变僵尸）

现象：修复崩溃后，Cmd+Q 关掉窗口但进程不退出（Dock 图标常驻，需要再按一次或强退）。

**定位过程（可复用的方法）**：写了一个临时 Playwright `_electron` 脚本复现 —— 启动应用后
`app.evaluate(({app}) => app.quit())`，再等进程 `exit` 事件。首次运行 15s 超时 → 稳定复现。
注意：本沙箱需 `--no-sandbox --disable-gpu` 且必须 `env -u ELECTRON_RUN_AS_NODE`（沙箱注入了该变量）。

**根因**（`src/main/index.ts` 的 `will-quit`）：

```ts
e.preventDefault()                 // 取消本次退出，先做异步清理
void c.shutdown().catch(...).finally(() => { ctx = null; app.quit() })  // ← 这句被忽略
```

`AppContext.shutdown()` 的每一步都是同步的（唯一 `await` 是 `sync.stop()`，未配置同步时 `await undefined`
立即 settle），因此整条链**在 `will-quit` 事件仍在派发的过程中**就以微任务完成。此时调用 `app.quit()`
会被 Electron 静默忽略 → 退出流程不再恢复 → 进程留在「无窗口但存活」状态。

验证：给 `will-quit` 再挂一个探针处理器，回退版本只看到一次 `before-quit`/`will-quit`；
而从外部（`app.evaluate`）稍后再调一次 `app.quit()` 则完整走出 `before-quit → will-quit → quit` 并以 0 退出。

**修复**：把最终退出推迟到事件派发结束之后。

```ts
.finally(() => { ctx = null; setImmediate(() => app.quit()) })
```

**回归保护**：新增 `tests/e2e/quit.spec.ts`（断言 `app.quit()` 后进程在 20s 内以 code 0 退出）。
已双向验证：回退 `setImmediate` 时该测试失败，修复后通过。e2e helper `tests/e2e/app.ts` 新增
`SSHTOOL_E2E_ARGS` 环境变量以透传额外 Chromium 参数（默认空，不影响正常运行的沙箱）。

验证：typecheck / eslint / vitest（170 passed）/ playwright e2e（8 passed，含新增用例）全部通过。

## 修复：关闭最后一个终端标签后跳到 SFTP（应为保险库）

根因（`src/renderer/src/stores/tabs.ts` 的 `closeTab`）：标签数组固定是 `[vault, sftp, ...终端]`
（`vault`/`sftp` 是 index 0/1 的固定标签），原来的兜底是

```ts
activeTabId = (tabs[idx] ?? tabs[idx - 1] ?? tabs[0]).id   // tabs 已过滤掉被关的标签
```

关掉最后一个终端时 `tabs[idx]` 越界，`tabs[idx - 1]` 正好是 index 1 的 **sftp**。

修复：在**终端标签**集合里找相邻者，找不到才回落到 `vault`：

```ts
const terminals = st.tabs.filter((t): t is TerminalTab => t.kind === 'terminal')
const pos = terminals.findIndex((t) => t.id === tabId)
activeTabId = (terminals[pos + 1] ?? terminals[pos - 1])?.id ?? 'vault'
```

顺带：给 `PinnedTab` 加了 `data-active={active}`，让固定标签的激活态可被测试断言（此前只有终端标签的
关闭按钮有 `data-active`）。

**回归保护**：新增 `tests/e2e/tab-close.spec.ts`，覆盖两种情况 —— 关闭多个终端中的活跃标签应激活相邻终端；
关闭最后一个终端应激活保险库（且 sftp 不活跃）。已双向验证：回退修复时该测试在「保险库应为活跃」断言处失败。

踩坑：测试里连点两次「打开本地终端」会失败，因为第一次点击后终端成为活跃标签、主机页被隐藏（这是正确行为）。
需先点 `[data-testid=tab-vault]` 切回再点按钮。

验证：typecheck / eslint / vitest（170 passed）/ playwright e2e（10 passed）全部通过。
